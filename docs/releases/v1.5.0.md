v1.5.0 — Audit evidence says what an answer was based on, and a release keeps its own decision / 审计证据说清答案基于什么，释放也留下自己的决定

Highlights

* Every target-status lookup now records a `basis`: `current_state` when the target answered from its live object store, `receipt` when it answered from its own acceptance record. A missing value reads as `unknown`, never as a current-state answer, so two `not_executed` readings that differ only in kind are distinguishable on the read face.
* The lookup history states what it could not have seen: whether the blind window is the stretch before the first reading or the whole life of the claim, how many seconds it spans, and the schedule's expected first ask — read from the plan the hourly sweep actually uses.
* A target-driven release writes its own `claim_release` decision row: who initiated it, what the target answered and when, the number of asks, and that the hold is released and re-claimable while the effect stays unknown. A later re-claim clears the hold row but cannot erase this one.
* A release row keeps the newest three readings off-chain (`release_lookups`), and `/audit/logs` exposes them as `releaseLookups`; a hold that was never queried says so in words.
* The console renders all of it in both languages: reading position, gap and claim time, the kind of each reading, and the blind-window statement.
* A release is bound to the view the reviewer saw: the body carries the frozen disposition and the newest reading's id, the write is conditional on the disposition still matching, and a ledger that moved underneath the screen is refused with `stale_view` — the refusal itself written as a `claim_release` row that states what the screen said against what the ledger says now.
* The pending-decision queue runs on two clocks, and neither one releases a hold: reading freshness only permits another ask, decision age only routes the row to a person, and a release still needs the target's explicit `not_executed` or a recorded decision at the deadline.

Also

* `check-release-texts.mjs` makes release coverage and tag-body identity a deterministic local gate; a new `smoke` job pulls the tag image and tests it before its Release exists.
* The commit-message order rule (English block first, Chinese block second, no `Co-Authored-By`) is now a CI gate, and `check-artifact-contract.mjs` reads the contract version a published Maven artifact declares.
* The no-renderer plan fallback honours the 4,000-character tool-result budget, and a renderer throw no longer turns a successful plan step into a failure.
* A failed lookup read leaves the claim untouched, so a release decision never lands without its record.
* Audit reads compare the user id as text, so a sweep-driven release no longer breaks an org-scoped audit list on Postgres; one failing reconcile row no longer spends the hour for the rest of the queue.
* One-click deployment generates or rejects published secrets, and the demo2 upstream is resolved per request so a missing stack answers 502 instead of taking nginx down.
* A release with no asks behind it says which kind of none it is — `lookups: none (never queried)` when a usable status query exists but nobody used it, `lookups: none (not askable — …)` when there is no channel to ask through at all — and the off-chain column carries `askable` as true, false or null, so the three cases stay countable.

亮点

* 每条目标状态查询现在记下「种类」（`basis`）：目标按当前对象存储作答记 `current_state`，按自己的受理记录作答记 `receipt`。缺值一律读作 `unknown`，绝不读成当前状态答案——于是两条仅种类不同的 `not_executed` 读数在读面上可以区分。
* 查询历史写明它看不到什么：盲区是首问之前那段，还是尚无读数时的整段占位；持续多少秒；以及计划里的预期首问等待——取每小时清扫实际所用的那份计划，而不是写死的数字。
* 目标驱动的释放留下自己的 `claim_release` 决定行：谁发起、目标答了什么、何时答的、问了几次，并写明占位已释放、可重占位、效果仍未知。之后的重占位会复用占位行，却抹不掉这一行。
* 释放行在链外保留最近三次读数（`release_lookups`），`/audit/logs` 以 `releaseLookups` 透出；从未查询过的占位明写「未查询」。
* 控制台以中英双语呈现全部读数：序位、间隔与写入时刻，每条读数的种类，以及盲区声明。
* 释放绑定在审阅者当时看到的视图上：请求体带上冻结的处置与最近一次读数的 id，写入以处置仍一致为条件；账本在屏幕下面变动过时以 `stale_view` 拒绝——拒绝本身也写成一条 `claim_release` 行，写明屏幕说的与账本现在说的。
* 待裁队列跑在两只时钟上，且两只都不释放占位：读数新鲜度只允许再问一次，决策年龄只把行交给一个人，释放仍须目标的明确 `not_executed`，或截止时已记录的决定。

其它

* `check-release-texts.mjs` 把发布文本覆盖与 tag 正文同源变成本地确定性门禁；新增 `smoke` 作业，先拉取该 tag 镜像再测，在产出 Release 之前拦住坏镜像。
* 提交信息顺序纪律（英文块在前、中文块在后、不带 `Co-Authored-By`）进了 CI 门禁；`check-artifact-contract.mjs` 读取已发布 Maven 构件自述的契约版本。
* 无渲染器的 plan 兜底也受 4,000 字符工具结果预算约束；渲染抛错不再把成功的 plan 步骤判为失败。
* 查询证据读取失败时占位保持原状，释放决定不会在缺少记录的情况下落地。
* 审计读按文本比较用户 id，目标驱动的释放不再让 Postgres 上的组织范围审计列表失败；一行对账失败也不再替队列里其余行花掉这个小时。
* 一键部署生成或拦截公开密钥；demo2 upstream 按请求解析，栈缺位时答 502，不再把 nginx 一起带下去。
* 一次都没问过的释放写明是哪一种「没有」——工具有可用的状态查询却没人用过写 `lookups: none (never queried)`，根本没有可问的通道写 `lookups: none (not askable — …)`——链外列以 `askable` 取 true / false / null 承载同一区分，使三种情形仍可计数。
