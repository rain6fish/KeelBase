# 多设备会话管理（AU-3）功能规格 / Multi-Device Session Management (AU-3) Feature Specification

## 1. 概述 / Overview

支持多设备同时登录，用户可查看已登录设备列表并远程登出。会话（refresh token）从 User 单列迁移为独立 `user_sessions` 表，每设备一行。

Supports simultaneous login on multiple devices; users can view the list of logged-in devices and log out remotely. Sessions (refresh tokens) move from a single column on User to a dedicated `user_sessions` table, one row per device.

## 2. 数据模型 / Data Model

`user_sessions` 表：

The `user_sessions` table:

| 字段 / Field | 类型 / Type | 说明 / Description |
|------|------|------|
| id | int PK | 会话 ID / Session ID |
| userId | int (index) | 所属用户 / Owning user |
| refreshHash | varchar(64) | refresh token 的 SHA-256 hash（权威凭据）/ SHA-256 hash of the refresh token (authoritative credential) |
| deviceId | varchar(64) | 设备标识（X-Device-Id 头）/ Device identifier (X-Device-Id header) |
| deviceName | varchar(128) | 设备名（登录时前端传入）/ Device name (sent by the frontend at login) |
| userAgent | varchar(255) | 浏览器 UA / Browser user agent |
| ip | varchar(64) | 登录 IP / Login IP |
| createdAt / lastActiveAt / expiresAt | datetime | 创建 / 最后活跃 / 过期（7 天）/ Created / Last active / Expiry (7 days) |

`User.refreshTokenHash` 单列保留（兼容），refresh/logout 主路径走会话表。

The single `User.refreshTokenHash` column is kept (for compatibility); the refresh/logout main paths use the sessions table.

## 3. API 规格 / API Specification

| Method | Path | Auth | 说明 / Description |
|--------|------|------|------|
| POST | /api/v1/auth/login | 公开 | 登录并登记会话行（读 X-Device-Id + body deviceName + IP）/ Login and register a session row (reads X-Device-Id + body deviceName + IP) |
| POST | /api/v1/auth/register | 公开 | 注册并登记会话行 / Register and register a session row |
| POST | /api/v1/auth/oauth | 公开 | OAuth 登录并登记会话行 / OAuth login and register a session row |
| POST | /api/v1/auth/refresh | 公开 | 按 refreshHash 查会话行校验 + 轮换（更新会话 hash 与活跃时间）/ Look up the session row by refreshHash for validation + rotation (update the session hash and active time) |
| POST | /api/v1/auth/logout | 登录 | 登出**当前设备**（按 deviceId 删会话行）；无 deviceId 时清全部 / Log out **the current device** (delete the session row by deviceId); clears all when no deviceId |
| GET | /api/v1/auth/sessions | 登录 | 当前用户会话列表（含 isCurrent 标记，读 X-Device-Id）/ Current user's session list (with isCurrent flag, reads X-Device-Id) |
| DELETE | /api/v1/auth/sessions/:id | 登录 | 远程登出指定会话（本人所有权）/ Remotely log out a specified session (own sessions only) |

## 4. 业务规则 / Business Rules

| 规则 / Rule | 说明 / Description |
|------|------|
| 多设备 | 每次登录登记独立会话行，互不覆盖 / Each login registers an independent session row; they never overwrite each other |
| refresh 校验 | 按 refreshHash 查会话行；用户 ID 不符 → 撤销该用户全部会话（防泄露）/ Look up the session row by refreshHash; user ID mismatch → revoke all of that user's sessions (leak protection) |
| 轮换 | refresh 成功后更新该会话行的 hash + lastActiveAt / After a successful refresh, update the session row's hash + lastActiveAt |
| 登出语义 | logout 只登出当前设备；远程登出（revoke）删指定会话 / logout only logs out the current device; remote logout (revoke) deletes the specified session |
| 过期 | 会话 7 天后过期（与 JWT_REFRESH_EXPIRES_IN 一致）/ Sessions expire after 7 days (matches JWT_REFRESH_EXPIRES_IN) |
| 所有权 | revoke 只能删本人会话，否则 401 / revoke can only delete the user's own sessions, otherwise 401 |
| 密码重置 | resetPassword 撤销该用户全部会话 / resetPassword revokes all of the user's sessions |

## 5. 前端 / Frontend

- `SessionProvider`：`load()` 拉会话列表、`revoke(id)` 远程登出（移除列表项）
  `SessionProvider`: `load()` fetches the session list, `revoke(id)` remotely logs out (removes the list item)
- `SessionListPage`（`/sessions`）：设备列表（名称 + 最后活跃 + 当前设备标记）+ 非当前设备尾部登出按钮 + 确认对话框 + toast
  `SessionListPage` (`/sessions`): device list (name + last active + current-device marker) + a logout button on non-current device rows + confirmation dialog + toast
- 入口：设置页「账户」分组「登录设备管理」
  Entry: Settings page → "Account" group → "Login Device Management"
- 登录请求带 `deviceName`（按平台生成：Windows/iPhone/Mac/Android/Web）
  Login requests carry `deviceName` (generated by platform: Windows/iPhone/Mac/Android/Web)
- ApiClient 已对所有请求带 `X-Device-Id` 头（`getOrCreateDeviceId()` 持久化）
  ApiClient already sends the `X-Device-Id` header on all requests (`getOrCreateDeviceId()` persisted)
