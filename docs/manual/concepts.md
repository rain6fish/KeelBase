# 概念地图 / Concept Map

> 目的：一页看懂 KeelBase 的核心词汇**以及它们之间的关系**。
> 新人卡住的通常不是单个词，而是「CASL 和 DataScope 到底谁管谁」这类**关系**问题。
> 读完这页再回到 [快速上手](quickstart.md) / [零基础教程](tutorial.md)，会顺得多。
>
> 本页是**索引**，不是权威定义——术语的权威以代码注释与 spec 为准。

---

## 0. 先分清两个 AI（最容易混的第一组）

KeelBase 里的「AI」有两个完全不同的身份，混了就看不懂架构：

| | **开发期 AI**（Build 层） | **运行时 AI**（Run 层） |
|---|---|---|
| 什么时候跑 | 你写代码的时候 | 用户用系统的时候 |
| 干什么 | 把业务规格变成**源码** | 在权限内**调用工具**替用户做事 |
| 入口 | `npx keelbase init --spec ...` | `/ai/chat`、管理台 AI 助手 |
| 产物 | 普通源码（你能改、能带走） | 审计行 + 副作用记录 |

**红线**：开发期 AI 生成的是**能走人的源码**，不是留在平台里的配置——这是 KeelBase 与传统低代码的分界。判据只有一条：产物是**留在平台的配置**，还是**能走人的源码 + 开放 Spec**。前者 = 低代码，后者 = KeelBase。

## 1. 一个模块是怎么来的

```
Business Spec（业务语言）
    ↓  访谈产出，或手写
Module Protocol（specs/*.json —— 结构化声明）
    ↓  npx keelbase init --spec
普通源码（entity / dto / service / controller + 接线 + 迁移 + 测试）
```

- **Business Spec** 是**构建期**输入模型，不进运行时契约。
- 生成器会自动完成**约 20 个接线点**——后端模块注册、CASL 角色规则、AI 工具注册、AI 导航、管理台路由/侧栏/i18n、Flutter 与 Taro 三端。**这些不是手工活。**

---

## 2. 授权 vs 数据范围（最容易混的第二组）

这两个词经常一起出现，但回答的是**两个不同的问题**：

| | **CASL**（授权） | **DataScope**（数据范围） |
|---|---|---|
| 回答 | 你能对**这类对象**做**什么动作** | 你能看到**哪些行** |
| 粒度 | 动作级（read / create / update / delete） | 行级（owner / dept / org） |
| 落点 | `src/common/casl/` | `src/common/scope/` |
| 例子 | `user` 只能 manage 自己的 Event | 「我部门所有人的待办」 |
| 不够用时 | 加 subject 规则 | 在 `SCOPE_COLUMNS` 登记该实体 |

**两者都要过**：CASL 说「你可以读 Todo」，DataScope 说「你只能读到这几行」。**缺任何一个都是漏洞。**

数据范围的档位（`ScopeLevel`）有 `all` / `own` / `own_dept_and_below` / `custom_dept` 等。一条降级规则值得记住：**缺组织/部门信息时一律退回本人**——收紧而非放宽。

---

## 3. 组织与部门

`Org`（组织）/ `Department`（部门，树形结构）/ 成员关系——这是**数据范围的来源**。实体上的 `orgId` / `deptId` 从这里填写，`DataScope` 也据此判定。

---

## 4. 写操作的门控：风险级

每个 AI 工具都带一个风险级，**它决定这个工具能不能自动执行**：

| 级 | 含义 | 处置 |
|---|---|---|
| R0 | 信息类 | 自动 |
| R1 | 读 | 自动 |
| R2 | 低风险写 | 由治理策略决定 |
| R3 | 业务敏感写 | **需人工确认** |
| R4 | 高影响动作 | **双人审批** |
| R5 | 不可逆 / 外部动作 | **阻断** |

配套词：

- **confirmation** —— 确认单（R3 的「等你点确认」）
- **revokeClass** —— 撤销档位（本地可补偿 / 外部受治理 / 不可撤），决定 UI 怎么诚实呈现「撤销」
- **副作用（Effect）** —— AI 写操作留下的记录，可撤销、可补偿

## 5. 审计有两条链（最容易混的第三组）

| | **AI 审计** `ai_audit_logs` | **操作审计** `operation_audit_logs` |
|---|---|---|
| 记什么 | AI 的行为（对话 / 工具调用 / 确认 / 撤销） | 人类的写操作（REST 写） |
| 谁写 | Agent 运行时 | 全局拦截器 |

**两条各自有哈希链**。而「**证据根**」（evidence-root）把某一个业务动作的**两条链 + 副作用 + 授权依据**绑成一个可离线校验的证据包。

---

## 6. 治理（Governance）

治理 = 决定「什么能自动跑」的那层策略：**工具开关、确认档位、角色白名单、审计粒度**。

它可以**独立部署**成治理台（多个业务系统的单一控制面），也可以只在系统本体生效；**sidecar** 让存量系统零代码接入同一套治理与审计。

---

## 7. 高频词速查

| 词 | 一句话 |
|---|---|
| **FeatureFlag** | 模块级开关，控制功能是否对外可见 |
| **Provenance** | 生成物的来源指纹（谁生成的、什么版本） |
| **MCP** | 把 AI 工具暴露/接入的标准协议（出口与网关两侧） |
| **Headless** | 用 API Key 调 AI，不需要前端 |
| **RAG** | 知识库检索增强，让回答有依据 |
| **FLOW** | 工作流引擎（人工任务 / AI 任务 / 条件节点） |
| **回收站** | 软删除记录，管理台可恢复 |
