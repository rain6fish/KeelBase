## 3. Four-layer review / 四层审核

Per `docs/manual/release-precheck.md`, four independent layers over the same range, then a consolidated decision. Findings are **recorded only**; nothing was fixed, by instruction.

### 3.1 Layer 1 — OpenCodeReview (OCR) / 第一层

23 findings across 40 files: **1 critical, 2 high, 9 medium, 11 low**. English summary of the substantive ones:

- **critical — `.github/workflows/docker-publish.yml` smoke job.** The image is pushed by another job on another runner, so it is not in the smoke runner's local daemon. `scripts/image-smoke.sh:60` runs `docker image inspect "$IMAGE"` as its first check, before any `docker run` could pull, and never pulls. The `smoke` job has no ghcr login or pull step. Verified in the workflow and the script.
- **high — `audit-query.service.ts` / `write-claim-decision.service.ts`.** A sweep-driven release writes `userId = 'system:sweep'` into `ai_audit_logs.user_id`. The column's documented invariant is a numeric string; `auditScopeSql` and the audit list's `orgId` filter emit `CAST(log.userId AS INTEGER)`. SQLite yields 0, Postgres raises `invalid input syntax for type integer`. Verified in all three files.
- **high — `ai-tool-effects.service.ts` reconcile pass.** `reconcileClaim` moves the hold to `released`, then awaits `recordTargetRelease`, which does two DB reads and a chained audit write. The per-pass loop has no per-row `try/catch`, so one throw aborts the hour for every remaining due claim — and the row that threw is already `released`, so the next pass will not pick it up. Verified: the loop body has no guard.
- **medium — `write-claim-query.service.ts` coverage after a re-claim.** Lookups are read by `idempotencyKey`, while a re-claim resets `claimedAt` on the same row. The first reading can predate the current claim, so `firstLookupAfterWriteSeconds` goes negative and `unobservedSeconds` clamps to 0 — the statement says the stretch was observed when it was not. Verified structurally.
- **medium — console history race.** `loadLookupHistory` assigns `lookupHistory` / `lookupCoverage` / gap refs after the await with no claim-id check, so a slow response for claim A can land on claim B's dialog.
- **medium — `types/admin.ts`.** `TargetStatusLookup` declares `seq` / `intervalSeconds` as required, but the same interface is used for `InFlightClaim.lastLookup`, which the server projects without them.
- **medium/low — tooling.** `check-artifact-contract.mjs`: manifest parsing does not stop at the main section's blank line; zip inflation is unbounded; a thrown error is indistinguishable from a real mismatch; a dead `pom.xml.sha1` guard; `readError` only surfaces in `--json` mode. `check-release-texts.mjs`: a common-prefix diff prints `<nothing>` on both sides. `deploy.sh`: the published-secret guard misses CRLF, quoted values and duplicate keys, and treats "absent" as "public". `image-smoke.test.sh` has no caller. `image-smoke.sh` is committed non-executable. `ci.yml` `git update-ref` failure message is unhelpful when the base commit is not fetched.

### 3.5 Consolidated decision / 整合结论

Three items are **release-blocking** and need the user's ruling (they are exactly the "record, do not fix" case this task set):

- **B-1 (postgres correctness).** `system:sweep` in `ai_audit_logs.user_id` breaks org-scoped audit reads on Postgres as soon as R-3 writes one row. Either stop writing a non-numeric actor into a numeric column (a documented sentinel with its own column, or `userId = '0'` plus the agent column), or make every cast tolerant. This is a shipped-feature defect, not a docs issue.
- **B-2 (release pipeline).** The `smoke` job cannot inspect an image it never pulled; every `v*` tag fails, and `sbom-release` never runs. Minimum fix: `docker/login-action` + `docker pull` in the smoke job (and `permissions: packages: read`).
- **B-3 (reliability).** One audit write failure aborts the hourly reconcile pass and loses the rest of the hour for every due claim. A per-row guard plus an error counter would make the pass resilient.

Everything else is low severity: comment order, i18n colon, doc drift in `CLAUDE.md`, the re-claim coverage path, the console race, the type over-declaration, the tooling nits. They do not stop a release; the re-claim coverage statement is the one worth fixing soon because it is the exact class of false coverage R-2 exists to prevent.
